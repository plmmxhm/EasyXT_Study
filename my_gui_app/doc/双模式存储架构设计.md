# 双模式数据存储架构设计

## 概述

实现两种独立的数据存储模式，用户可根据需求选择：

1. **Parquet模式（默认）**：保存到Parquet文件，通过DuckDB视图查询
2. **数据库表模式**：直接保存到DuckDB物理表中，查询时直接读取表

---

## 架构设计

### 模式对比

| 特性 | Parquet模式 | 数据库表模式 |
|------|------------|------------|
| **存储位置** | Parquet文件系统 | DuckDB数据库内部 |
| **查询方式** | 通过视图映射Parquet | 直接查询物理表 |
| **优势** | 文件可移植、可备份 | 查询速度快、无需视图维护 |
| **适用场景** | 长期归档、大数据量 | 快速查询、频繁更新 |

### 数据流对比

```
【Parquet模式】（当前默认）
下载API → DataFrame → 保存Parquet → 创建/刷新视图 → 查询视图

【数据库表模式】（新增）
下载API → DataFrame → 直接INSERT到DuckDB表 → 查询物理表
```

## 关键代码示例

### database_table_manager.py 核心方法

```python
class DatabaseTableManager:
    """数据库表直接存储管理器"""
    
    def __init__(self, db_path: str):
        self.db_path = db_path
        self.conn = None
    
    def save_to_table(self, df: pd.DataFrame, table_name: str, 
                      data_type: str) -> Tuple[bool, str]:
        """
        将DataFrame直接保存到DuckDB物理表
        
        Args:
            df: 要保存的数据
            table_name: 目标表名（如 stock_daily）
            data_type: 数据类型（1d, 1w, 1M等）
            
        Returns:
            (success, message)
        """
        try:
            # 连接数据库
            conn = duckdb.connect(self.db_path, read_write=True)
            
            # 清理数据（确保列名和数据类型正确）
            df_clean = self._prepare_dataframe(df, data_type)
            
            # 使用INSERT INTO批量插入
            # 如果数据已存在，先删除旧数据或使用UPSERT
            conn.execute(f"INSERT INTO {table_name} SELECT * FROM df_clean")
            
            return True, f"成功保存 {len(df_clean)} 条记录到 {table_name}"
            
        except Exception as e:
            return False, f"保存失败: {str(e)}"
        finally:
            if conn:
                conn.close()
    
    def get_table_stats(self, table_name: str) -> Dict:
        """获取表的统计信息"""
        conn = duckdb.connect(self.db_path, read_only=True)
        
        result = conn.execute(f"""
            SELECT 
                COUNT(*) as record_count,
                MIN(date) as min_date,
                MAX(date) as max_date,
                COUNT(DISTINCT stock_code) as symbol_count
            FROM {table_name}
        """).fetchone()
        
        conn.close()
        
        return {
            'record_count': result[0],
            'min_date': str(result[1]) if result[1] else None,
            'max_date': str(result[2]) if result[2] else None,
            'symbol_count': result[3]
        }
```

### parquet_manager.py 修改示例

```python
def save_data(self, df, data_type, metadata=None, temp_strategy='direct'):
    """
    统一的数据保存入口
    
    根据配置决定保存方式：
    - 'direct' 或 'parquet': 保存到Parquet文件
    - 'database': 直接保存到DuckDB表
    """
    
    storage_mode = self.config.get('storage', {}).get('data_source', {}).get('mode', 'parquet')
    
    if storage_mode == 'database':
        # 【新增】数据库表模式
        return self._save_to_database_table(df, data_type, metadata)
    else:
        # 【原有】Parquet模式
        if temp_strategy == 'direct':
            return self._save_to_parquet_direct(df, data_type, metadata)
        else:
            # temp策略已弃用，统一使用direct
            return self._save_to_parquet_direct(df, data_type, metadata)

def _save_to_database_table(self, df, data_type, metadata):
    """保存到数据库表的新方法"""
    from .database_table_manager import DatabaseTableManager
    
    db_manager = DatabaseTableManager(self.db_path)
    table_name = self._get_table_name(data_type)  # 如 stock_daily
    
    success, message = db_manager.save_to_table(df, table_name, data_type)
    
    if success:
        logging.info(f"✅ 数据库表模式: {message}")
        return (True, message, f"table:{table_name}")
    else:
        logging.error(f"❌ 数据库表模式失败: {message}")
        return (False, message, None)
```

## 风险和缓解措施

### 风险1: 数据不一致
**缓解**: 提供数据校验工具，定期检查两种数据源的差异

### 风险2: 数据库文件过大
**缓解**: 
- 定期清理历史数据
- 支持分区表（按年/月分区）
- 提供压缩选项

### 风险3: 并发冲突
**缓解**: 
- DuckDB支持WAL模式
- 写入时加锁
- 批量操作减少锁竞争

## 总结

本设计实现了灵活的双模式数据存储架构，满足不同场景需求：
- **日常快速查询**: 使用数据库表模式
- **长期数据归档**: 使用Parquet模式
- **平滑过渡**: 两种模式可并存和互迁
