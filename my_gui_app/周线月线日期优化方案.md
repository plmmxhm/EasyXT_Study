## 🔬 关键发现

### 1️⃣ **count参数行为** ✅

| 参数组合 | 返回结果 | 说明 |
|---------|---------|------|
| 所有参数缺省 | 426条周线，最新: **20260412** | 返回本地全部数据 |
| count=-1 | 同上 | 显式获取全部 |
| count=5 | 最新5条，包含20260412 | 只返回最新N条 |
| count=1 | **1条，日期20260412** | 获取最新单条K线 |

**结论**: `count`参数完全符合文档描述！

---

### 2️⃣ **周线数据 - 周六能否获取本周？** ✅

#### 测试场景：今天是周六(4/11)

```
查询方式                    返回结果              是否合理
─────────────────────────────────────────────────────
所有参数缺省                最新: 20260412        ✅ 本周周线！
start=4/1, end=4/11         1条: 20260405         ⚠️ 上周（因为本周还没完整结束在API视角）
count=1                     1条: 20260412         ✅ 最新就是本周！
end_time=4/11(只指定结束)    425条, 最新: 20260405  ⚠️ 不含本周
```

**重要发现**:
- ✅ **周六可以获取本周周线数据**
- 周线索引 = 该周最后一个交易日（如20260412表示4/6-4/11那周）
- 使用 `count=1` 可以直接获取最新周线

| 查询方式 | 返回的月线条数 | 最新日期 | 是否合理 |

**🎯 关键结论**:
```python

# ✅ 正确做法：指定end_time为用户查询的结束日期
get_market_data_ex(period='1mon', end_time='20260411')
# → 返回20260331 (3月末) ← 用户明确知道只有到3月的数据
```

### 4️⃣ **API智能过滤机制** 💡

通过测试发现，QMT API具有**内置的智能过滤逻辑**：

#### 月线过滤规则：
```
用户查询: start=20260101, end=20260315 (3月15日)

API内部处理:
1. 获取所有已缓存的月线K线
2. 过滤条件: K线索引日期 ≤ end_time (20260315)
3. 3月的K线索引是20260331 (月末)
4. 因为 20260331 > 20260315，所以3月K线被过滤掉
5. 最终返回: ..., 20260228 (2月末) ← 最后一条有效数据 ✅
```

#### 周线过滤规则：
```
用户查询: start=20260401, end=20260411 (4月11日，周六)

API内部处理:
1. 获取所有已缓存的周线K线
2. 过滤条件: K线索引日期 ≤ end_time (20260411)
3. 本周的K线索引是20260412 (本周六)
4. 因为 20260412 > 20260411，所以本周K线被过滤掉 ❌
5. 最终返回: 20260405 (上周五) ← 如果严格按日期过滤

但是！如果使用count参数：
count=1 → 直接返回最新的20260412 (不按日期过滤) ✅
```

## ✅ 最终解决方案

### 核心原则：**信任API的智能过滤能力**

根据测试结果，最优策略非常简单：

```python
def download_single_symbol(self, symbol, start_date, end_date):
    # 【开始日期】前向扩展到周期起点
    # - 周线 → 扩展到周一
    # - 月线 → 扩展到月初
    # 目的：确保能获取到该周期的完整K线
    
    # 【结束日期】直接使用用户指定的日期！不做任何扩展！
    # API会自动过滤出 ≤ end_date 的最新完整周期K线
    
    adjusted_start = expand_to_period_start(start_date)
    adjusted_end = end_date  # ← 关键：不过度延伸
    
    data = get_market_data_ex(
        period=period,
        start_time=adjusted_start,
        end_time=adjusted_end  # ← 让API智能过滤
    )
    
    return data  # ← 返回的数据已经是正确的了！
```

## 📚 API文档参考

根据[迅投官方文档](https://dict.thinktrader.net/nativeApi/xtdata.html):

> **count参数说明**:
> - int类型，数据个数
> - 默认参数
> - 大于等于0时：
>   - 若指定了start_time、end_time → 以end_time为基准向前取count条
>   - 若start_time、end_time缺省 → 默认取本地数据最新的count条数据
>   - 若start_time、end_time、count都缺省时 → 默认取本地全部数据

**我们的策略完美契合这个设计！**
